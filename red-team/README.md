# Red Team

Authorized offensive-security labs and CTF exercises, documented with an emphasis on methodology and defensive lessons.

## Focus areas

- Reconnaissance and enumeration
- Web application security
- Vulnerability identification and validation
- Linux and Windows security concepts
- Privilege and access-control concepts
- Attack-path analysis in intentionally vulnerable labs
- Reporting findings and remediation

## Rules of engagement

- Work only on systems explicitly provided for training or where clear authorization exists.
- Keep testing inside the lab's stated scope.
- Never test public, workplace, school, or third-party systems without explicit permission.
- Do not publish working credentials, tokens, flags, or sensitive target data.
- Avoid turning lab notes into instructions for compromising real systems.

## Write-up expectations

Document the objective, authorized scope, methodology, evidence, impact, and remediation. Explain how defenders could detect or prevent the behavior. Do not claim a vulnerability or outcome unless it was personally verified in the lab.

Use the [write-up template](../templates/WRITEUP-TEMPLATE.md).
