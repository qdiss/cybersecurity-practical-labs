# Cybersecurity Practical Labs

A practical portfolio of cybersecurity labs, CTFs, and investigations focused on building hands-on skills across defensive security, offensive security, and core security fundamentals.

**Author:** [Adis Klobodanović](https://github.com/qdiss)  
**GitHub:** [@qdiss](https://github.com/qdiss)

## Focus

This repository documents practical work completed in authorized training environments. It is organized around three areas:

| Area | Target share | Focus |
|---|---:|---|
| Blue Team | 50% | Security monitoring, log analysis, incident investigation, threat hunting, detection engineering, and DFIR |
| Red Team | 30% | Methodology, enumeration, vulnerability analysis, and exploitation concepts in intentionally vulnerable labs |
| General & Fundamentals | 20% | Networking, operating systems, scripting, security concepts, and supporting tools |

These percentages describe the intended learning balance, not a claim about completed work.

## Repository structure

- `blue-team/` — defensive labs and investigations
- `red-team/` — authorized offensive-security training
- `general-and-fundamentals/` — core technical and security foundations
- `challenge-catalogue/` — planned and completed challenge index
- `templates/` — reusable write-up template
- `resources/` — references and learning resources

## Write-up standards

- Write-ups are published in English.
- Findings are based on work actually performed and evidence actually observed.
- No fabricated results, flags, credentials, screenshots, or completion claims.
- Sensitive values are redacted from published evidence.
- Challenge pages distinguish planned work from completed work.
- Platform difficulty and estimated completion time are included only when they can be verified.

## Scope and ethics

All offensive-security activity must remain within platforms, systems, and environments where explicit authorization has been granted. Do not use techniques documented here against third-party systems without permission. Red Team write-ups should also explain relevant defensive lessons where appropriate.

## Learning approach

This repository complements my [SOC Level 1 TryHackMe learning path](https://github.com/qdiss/SOC-Level-1-Path-THM). That repository tracks a structured learning path; this one is intended for practical challenge notes, investigations, and technical write-ups.
